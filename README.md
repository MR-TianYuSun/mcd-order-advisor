# 🍔 麦麦省钱决策引擎 (McDonald's Order Advisor)

> 基于 **麦当劳中国 MCP** 的「自然语言点餐 + 组合省钱求解 + 多约束决策」智能体 Skill。
> 一句话需求 → 具体、可下单、**实付最低**的方案。

麦当劳官方 App 给你一堆优惠券，但**从不替你算"全券最优组合 × 套餐替换 × 多人凑单"**。本引擎把 `calculate-price` 当成"价格预言机"，用组合搜索求出真正的最低实付——这是 LLM + 工具 才有的玩法，App 做不到。

---

## ✨ 它解决什么痛点

- **券太多不会凑**：麦麦省券 + 门店券 + 我的券三路并行，`calculate-price` 实测哪组最省。
- **不知道怎么点最划算**：从"推荐几个好吃的"升级为"枚举候选 × 价格预言机 → 最低实付"。
- **多人/团建点单累**：自动做份量分配、并单触发大额满减。
- **有忌口要手动改**：自动去酱/换无糖/换配料，无需反复确认。
- **健身/控糖/带娃场景**：垂直模式做蛋白优先 / 低卡优先 / 亲子优先排序。

## 🚀 核心能力

| 能力 | 说明 |
|---|---|
| **省钱组合求解器** | 枚举 3–6 个候选篮子（基础餐品×替换项×券组合），逐个调 `calculate-price`，取实付最低 |
| **多人/团建份量规划** | 人均预算分配、避免重复、并单用大额券 |
| **忌口约束自动求解** | 从套餐可替换项自动满足忌口，无替换可满足才追问 |
| **垂直人群模式** | 健身(高蛋白) / 控糖(低卡) / 亲子，带「仅供参考」免责 |
| **场景自适应** | 堂食 / 外送 / 到店取、单人 / 多人全覆盖 |
| **合规可控** | 数据全来自官方 MCP、不编造；下单前必须用户确认 |

## 💡 省钱求解示意

> 以下为流程示意，实际数字以运行 `calculate-price` 的实时返回为准。

```
需求："2人、想吃辣、预算人均30、要最省"
  → 取候选：麦辣鸡腿堡套餐 / 板烧鸡腿堡套餐 / 辣翅分享盒 ...
  → 枚举篮子：
      篮子① 麦辣套餐×2 + 门店满50减8      → calculate-price → 实付 ¥52
      篮子② 板烧套餐×2 + 麦麦省券          → calculate-price → 实付 ¥49  ← 最低
      篮子③ 辣翅盒 + 单点 + 凑满减          → calculate-price → 实付 ¥55
  → 主推篮子②：实付 ¥49，比次优再省 ¥3 🎉
```

## 🧩 技术架构

```
自然语言需求
   └─> 需求解析（场景/人数/预算/忌口/人群词）
         └─> now-time-info 锚定时段
               └─> 选门店（外送/到店分支）
                     └─> query-meals + query-meal-detail（候选 + 替换项）
                           └─> 三路券并行（store / 麦麦省 / 我的券）
                                 └─> ★ 省钱组合求解器（枚举篮子 × calculate-price）
                                       └─> 垂直模式（多人 / 忌口 / 人群）
                                             └─> 综合输出 → 用户确认 → create-order
```

详见 [`MCP_INTEGRATION.md`](./MCP_INTEGRATION.md) 与 [`references/decision-workflow.md`](./references/decision-workflow.md)。

## ⚡ 快速开始

1. 到 `open.mcd.cn/mcp` 用手机号验证申请 **MCP Token**。
2. 在 WorkBuddy 连接器配置 MCP（见 `mcp-config.example.json`），把 Token 填入环境变量 `MCD_MCP_TOKEN`。
3. 安装本 Skill 到 `~/.workbuddy/skills/mcd-order-advisor/`。
4. 在对话中直接用自然语言点单，例如："帮我点麦当劳，两个人想吃辣的，预算 40，要最省"。

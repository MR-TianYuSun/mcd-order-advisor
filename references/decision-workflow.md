# 决策工作流详解（开发者参考）

本文档面向想二次开发 / 校验本 Skill 的开发者，补充 `SKILL.md` 中决策流的工程细节。v2 新增：省钱组合求解器、多人/团建份量规划、忌口约束自动求解、垂直人群模式。

## 1. 需求抽取字段表

| 字段 | 取值示例 | 默认值 | 缺失处理 |
|---|---|---|---|
| 场景 | 早餐/午晚餐/夜宵/下午茶 | 由 `now-time-info` 推断 | 优先用时间推断 |
| 人数 | 1 / 8 | 1 | 不追问，按单人跑 |
| 预算上限 | ¥25（人均或总） | 不限 | 不限时按推荐组合出价 |
| 口味偏好 | 辣/甜/清淡 | 无 | 不过滤 |
| 忌口 | 不要香菜/去酱/无糖 | 无 | 不过滤；进入忌口自动求解 |
| 就餐方式 | 堂食/外送/到店取 | 堂食 | 堂食优先 |
| 要优惠 | 是/否 | 否 | 默认给基础推荐 + 一句询问 |
| 关心营养 | 是/否 | 否 | 不调营养工具 |
| 人群词 | 健身/控糖/亲子 | 无 | 不触发垂直模式 |

## 3. 省钱组合求解器（核心）

普通"推荐"只调一次 `calculate-price`；本引擎**主动搜索最优组合**：

1. **候选集**：`query-meals` + `query-meal-detail`（取替换项）得 4-8 个候选。
2. **枚举篮子（3-6 个）**，每篮 = {基础餐品 + 替换项 + 券组合}，刻意覆盖：
   - 策略 A 满减凑单：加/换商品跨过满减门槛，验证净省。
   - 策略 B 替换平价：换无糖/去酱/换小杯，看单价变化。
   - 策略 C 并单用大额券：多人并单触发大额满减。
3. **并行 `calculate-price`**：每篮传入商品编码+替换项+券 ID，取 原价/优惠/配送费/应付。
4. **比较取最低**：满足全部约束下选实付最低篮；次低作备选并说明差额。
5. **解释**：写明用了哪些券/替换、省了多少。

> 铁律：金额差只来自 `calculate-price` 返回，禁止前端加减。篮子 ≤ 6，控频防 429。

### 3.4 `calculate-price` 调用规范（真实 schema）

**入参**：`storeCode / orderType / beType` 必填；得来速(beType=5)/外送(beType=2)/团餐(beType=6) 必传 `beCode`（来自门店查询返回）。
- `orderType`：1=到店（含自取+DT），2=外送（含麦乐送+团餐）
- `items[]`：
  - 单品：`{ productCode, quantity }`
  - 套餐替换项：`roundList:[{ round, comboItemList:[{ code, quantity, modification? }] }]`
  - 特制（去酱/加减料）：`modification:{ values:[{ code, key, quantity }] }`
  - 挂券：把券的 `couponCode` / `couponId` 填到对应 item（券取自 `query-store-coupons` / `query-my-coupons`）

**出参**：`data.price`（应付，★比较基准）、`data.originalPrice`（原价）、`data.discount`（优惠）、`data.productList[]`、`data.takeWayList[]`。**所有金额单位为「分」**（如 `price:4580` = ¥45.80），展示前务必 ÷100。

### 3.5 容错策略
- **429**：降频重试；仍频繁则篮子数降到 3。
- **某路券为空**：跳过该路，不报错。
- **套餐 roundList 不全 / beCode 缺失**导致 `calculate-price` 报错：读错误信息补全后重试 1 次；仍失败则丢弃该篮子。
- **忌口无替换**：仅在 `query-meal-detail` 确认无任何可替换项满足时才追问用户。

## 4. 垂直模式实现要点

### 4.1 多人 / 团建份量规划
- 抽 N 与预算（总/人均）。
- 份量分配避免重复单品；团建可**并单**一笔订单触发满减，用 `calculate-price` 验证比分开点更省。
- 输出：每人餐品 + 整单汇总 + 人均。

### 4.2 忌口约束自动求解
- 从 `query-meal-detail` 读套餐可替换项（饮料/酱料/配料）。
- 自动选满足忌口的替换（去酱/换无糖/不要生菜），不追问；**仅当无替换可满足时**才追问。

### 4.3 特定人群模式（关键词触发）
| 触发词 | 模式 | 行为 | 免责 |
|---|---|---|---|
| 健身/增肌/高蛋白 | 蛋白优先 | `list-nutrition-foods` 标蛋白，优先高蛋白少油炸 | 仅供参考 |
| 控糖/减脂/低卡 | 低卡优先 | 优先低能量无糖饮料，汇总能量碳水 | 仅供参考 |
| 亲子/带娃/宝宝 | 亲子模式 | 推开心乐园餐、避辣、提示儿童份量 | 仅供参考 |

## 5. 计价与下单

- `calculate-price` 入参：商品列表（含套餐编码与替换项）+ 选用券 ID。
- 返回：商品金额、配送费、优惠金额、应付总价。
- 输出方案 → **等待用户明确确认** → `create-order` 返回支付链接。
- 任何下单动作前都必须有用户确认，避免误操作产生真实订单。

## 6. 合规护栏（提示词层面）

- 营养/人群数据输出必带「仅供参考，非专业建议」后缀。
- 不主动推荐暴食 / 奢华组合，避免触达「宣扬不健康饮食 / 奢靡浪费」红线。
- 所有麦当劳数据来自 MCP，提示词层面禁止"凭经验编造餐品/价格/优惠"。
- 凭证只从 `${MCD_MCP_TOKEN}` 读取，仓库内绝不出现明文 Token。
- 求解器枚举篮子数 ≤ 6，控制 `calculate-price` 调用频率避免 429。
